# 長時間掛機與自動恢復使用說明

本文件說明 `run.bat` 的 Supervisor 啟動方式、Native／Sandbox 雙實例隔離，以及異常後如何自動恢復。適用於長時間掛機時，遊戲視窗失效、程式例外、截圖失敗或 bot 卡住的情境。

## 啟動方式

請從專案根目錄執行：

```bat
run.bat
```

依序完成：

1. 選擇模式與首次設定，例如每日、地下城、推圖。
2. 選擇祝福（適用於每日／地下城／混合模式）。
3. 選擇目標實例：
   - `1`：Native Steam
   - `2`：Sandbox Steam

啟動列中應出現下列參數之一，這是確認目標已被固定的方式：

```text
--target native --profile native
```

```text
--target sandbox --profile sandbox
```

不要直接以 `python main.py` 作為長時間掛機入口；那樣會略過外層 Supervisor。

## Native 與 Sandbox 可同時執行

可開兩個獨立的 `run.bat` 視窗：一個選 Native，另一個選 Sandbox。兩者會使用不同 profile 與 heartbeat 檔案：

| 實例 | Profile | Heartbeat |
| --- | --- | --- |
| Native | `native` | `scratch/runtime/heartbeat_native.json` |
| Sandbox | `sandbox` | `scratch/runtime/heartbeat_sandbox.json` |

因此兩個實例不會因為彼此的存活訊號而誤判卡死。各 profile 的設定也分別儲存在 `user_data/<profile>/`。

## Supervisor 會重啟什麼？

Supervisor 是外層 Python 程序，子程序才是實際執行 bot 的 `main.py`。

| 狀況 | 執行動作 |
| --- | --- |
| `main.py` 例外結束 | Supervisor 重啟 `main.py` |
| 手動結束只有 `main.py` | Supervisor 重啟 `main.py` |
| 按 `Ctrl+C` | Supervisor 重啟 `main.py` |
| heartbeat 超過 180 秒未更新 | Supervisor 結束並重啟 `main.py` |
| 連續五次截圖失敗 | bot 先嘗試重啟遊戲；失敗才讓 Supervisor 重啟 bot |
| `Ctrl+Shift+Q` | 明確停止 Supervisor，回到 `run.bat` 的重新啟動選單 |

首次啟動可能需要使用者回答 CLI 問題，因此首次啟動的等待上限是 10 分鐘。後續自動恢復啟動則使用 180 秒 heartbeat 上限。

## 自動重啟後為何不會再要求輸入？

第一次啟動時，你選擇的關卡、地下城策略、裝備保留策略與 profile 設定會保存到 profile 設定檔。Supervisor 重新啟動時會保留原本模式、目標與 profile，並加上：

```text
--resume
```

`--resume` 會跳過 CLI 問題，直接讀取同一個 profile 的已保存設定，並重建執行時需要的地下城／關卡導航路徑。

## 快捷鍵

| 快捷鍵 | 行為 |
| --- | --- |
| `Ctrl+Space` | 暫停／繼續 bot |
| `Ctrl+C` | 視為需要恢復，Supervisor 會重啟 bot |
| `Ctrl+Shift+Q` | 使用者明確停止；返回批次檔選單，可選擇是否重新啟動 |

若只是想讓程式恢復，不需要關閉整個終端機；可以手動結束名稱或命令列含 `main.py` 的子程序，外層 Supervisor 會重新建立它。不要結束命令列含 `runtime.supervisor` 的父程序，否則自動恢復層也會一併停止。

## 檢查是否正常運作

執行約十秒後，在 PowerShell 檢查 heartbeat：

```powershell
Get-Content .\scratch\runtime\heartbeat_native.json
```

Sandbox 改為：

```powershell
Get-Content .\scratch\runtime\heartbeat_sandbox.json
```

內容應包含 `pid`、`state`、`target`、`profile` 與 `timestamp`。`timestamp` 約每十秒更新一次。

也可查看父子程序關係：

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'runtime.supervisor|main.py' } |
  Select-Object ProcessId, ParentProcessId, CommandLine
```

應看到一個命令列含 `runtime.supervisor` 的父程序，以及一個命令列含 `main.py` 的子程序。

## 安全驗證自動恢復

1. 先以 `run.bat` 成功啟動一個實例。
2. 確認 heartbeat 已持續更新。
3. 只結束命令列含 `main.py` 的子程序。
4. 約兩秒後，Supervisor 應印出新的 `Starting bot process`；命令列含相同的 `--target`、`--profile`，並多出 `--resume`。
5. 新程序不應再詢問模式、祝福、關卡或目標實例。

若要測試遊戲視窗恢復，請在非重要戰鬥中關閉目標遊戲視窗。bot 會在連續五次截圖失敗後嘗試重新開啟遊戲。

## 常見問題

### 出現 `'instance' is not recognized` 或類似錯誤

這表示使用了舊版或換行格式錯誤的 `run.bat`。請關閉該終端機後，使用本次更新後的 `run.bat` 重新啟動；不要沿用已經開啟的舊視窗。

### 一開始就顯示 heartbeat stale

Supervisor 現在只接受本次子程序啟動後更新的 heartbeat，舊檔不會觸發誤判。若仍出現，確認啟動列有正確的 `--target` 與 `--profile`，並檢查對應 heartbeat 檔是否在十秒內更新。

### 想完全退出，不想自動重啟

請使用 `Ctrl+Shift+Q`，不要使用 `Ctrl+C`。程式回到批次檔選單後輸入 `Q` 即可離開。
